# Сброс пароля администратора 1С

Инструкция описывает восстановление доступа к своей базе 1С, когда утерян пароль
администратора. Сбрасывается только пароль администратора — **остальные учётные
записи не страдают**. Способ подходит для всех современных конфигураций 1С.

!!! danger "Перед началом"

    - Сделай **резервную копию базы** — все действия ниже правят служебные таблицы.
    - Работы выполняются на своём сервере, с правами администратора СУБД.
    - Клиентские сеансы 1С на время процедуры лучше завершить.

---

## Принцип работы

Список пользователей и хэши их паролей 1С хранит в служебной таблице `v8users`,
а признак наличия списка — в таблице `Params` (запись `users.usr`).

Если временно «спрятать» и то и другое, платформа считает, что список
пользователей пуст, и пускает в базу **без запроса логина и пароля**. После
входа таблицы возвращаются на место, и пароль администратора меняется штатными
средствами 1С.

Порядок один и тот же для любой СУБД:

1. Переименовать `v8users` и запись в `Params`.
2. Зайти в 1С — вход произойдёт без выбора пользователя.
3. **Не выходя из 1С** вернуть таблицы обратно.
4. Сменить пароль администратора в 1С.

!!! warning "Не закрывай 1С между шагами 2 и 3"

    Сеанс должен оставаться открытым, пока таблицы возвращаются на место.
    Если закрыть 1С раньше, придётся повторять процедуру с начала.

## Вариант 1. MS SQL Server

Открой **SQL Server Management Studio** → *Создать запрос*.

### Шаг 1. Спрятать список пользователей

```sql
USE [ИмяБазы];  -- замени на имя своей базы 1С
GO
EXEC sp_rename 'v8users', 'v8users_bak';
GO
UPDATE [Params]
SET [FileName] = 'users.usr_bak'
WHERE [FileName] = 'users.usr';
GO
```

Нажми **Выполнить**.

### Шаг 2. Войти в 1С

Запусти 1С с этой базой — вход произойдёт без выбора учётной записи.

### Шаг 3. Вернуть таблицы на место

Переключись в Management Studio, **не закрывая 1С**, и выполни:

```sql
USE [ИмяБазы];  -- замени на имя своей базы 1С
GO
DROP TABLE [v8users];
GO
EXEC sp_rename 'v8users_bak', 'v8users';
GO
UPDATE [Params]
SET [FileName] = 'users.usr'
WHERE [FileName] = 'users.usr_bak';
GO
```

### Шаг 4. Сменить пароль

Вернись в 1С и смени пароль администратору.

## Вариант 2. PostgreSQL через pgAdmin 4

Открой pgAdmin, щёлкни по нужной базе правой кнопкой → **Query Tool**.

### Шаг 1. Спрятать список пользователей

```sql
ALTER TABLE v8users RENAME TO v8users_bak;
UPDATE params SET filename = 'users.usr_bak' WHERE filename = 'users.usr';
```

!!! note "Про имя резервной таблицы"

    В PostgreSQL идентификатор с дефисом (`v8users_tuning-admina`) без двойных
    кавычек вызывает синтаксическую ошибку — дефис читается как минус. Поэтому
    здесь и далее используется `v8users_bak` с подчёркиванием.

### Шаг 2. Войти в 1С

Запусти 1С с этой базой — вход произойдёт без выбора учётной записи.

### Шаг 3. Вернуть таблицы на место

Переключись в pgAdmin, **не закрывая 1С**:

```sql
DROP TABLE v8users;
ALTER TABLE v8users_bak RENAME TO v8users;
UPDATE params SET filename = 'users.usr' WHERE filename = 'users.usr_bak';
```

### Шаг 4. Сменить пароль

Вернись в 1С и смени пароль администратору.

## Вариант 4. Файловая база

В файловой базе таблицы через СУБД не переименовать — пароль правится прямо
в файле `1Cv8.1CD`. Порядок действий:

1. Резервная копия базы.
2. Откат версии формата базы данных.
3. Правка хэша пароля администратора.
4. Возврат версии формата обратно.
5. Тестирование и исправление.

Пример ниже — платформа `8.3.22.2283`, конфигурация ЗУП 3.1. Подставь свою
версию платформы и свой путь к базе.

### Шаг 1. Резервная копия

Просто скопируй папку с базой. Все манипуляции безопаснее сначала проделать
на копии.

### Шаг 2. Откатить версию формата базы

Утилита `tool_1cd` умеет **редактировать** базу только до версии 0.3.0, а она
работает с форматом БД не выше 8.2.14. В свежих конфигурациях формат — 8.3.8,
поэтому его нужно временно понизить.

Запусти командную строку **от имени администратора**:

```cmd
"C:\Program Files\1cv8\<версия платформы>\bin\cnvdbfl.exe" -c -f 8.2.14 "<путь к базе>\1Cv8.1CD"
```

Пример с конкретными значениями:

```cmd
"C:\Program Files\1cv8\8.3.22.2283\bin\cnvdbfl.exe" -c -f 8.2.14 "D:\DataBases\zup\1Cv8.1CD"
```

Процедура занимает около минуты.

### Шаг 3. Заменить хэш пароля

Понадобится **Tool_1CD версии 0.3.0** — сторонняя утилита для просмотра
и редактирования файла `1Cv8.1CD`. Скачивай её из источника, которому доверяешь,
и проверяй файл антивирусом: в новых версиях редактирование убрано, поэтому
в сети распространяются разные пересборки.

Порядок:

1. Открой в Tool_1CD файл `1Cv8.1CD` своей базы.
2. Найди таблицу `V8USERS` — в ней список пользователей.
3. В строке пользователя **Администратор** выдели ячейку `Data` (тип `Image`).
4. Внизу нажми на иконку дискеты и сохрани содержимое в файл.
5. Открой этот файл в текстовом редакторе.

Внутри в кавычках будут три значения хэшей: два одинаковых и одно отличающееся.
Это хэши пароля администратора. Замени их на хэш **пустого** пароля:

```text
2jmj7l5rSw0yVb/vlWAYkK/YBwk=
```

Пример исходного значения, которое нужно заменить:

```text
hW3M4CbxT84tr2MR9JbjD0jsROM=
```

Сохрани файл. Затем в Tool_1CD:

1. Нажми на иконку карандаша — режим редактирования.
2. Нажми иконку загрузки и укажи путь к исправленному файлу.
3. Убедись, что импорт прошёл успешно.
4. Нажми иконку с зелёной галочкой — сохранение изменений в базу.

Закрой Tool_1CD, дальше она не нужна.

### Шаг 4. Вернуть версию формата базы

```cmd
"C:\Program Files\1cv8\<версия платформы>\bin\cnvdbfl.exe" -c -f 8.3.8 "<путь к базе>\1Cv8.1CD"
```

!!! warning "Версия формата"

    Возвращай тот же формат, который был до отката (у свежих конфигураций —
    `8.3.8`). Проверить текущую версию можно в конфигураторе:
    *Справка → О программе*.

### Шаг 5. Тестирование и исправление

Запусти базу в режиме **Конфигуратор** → *Администрирование → Тестирование
и исправление*. Галочки оставь по умолчанию, нажми **Выполнить**. Если с базой
изначально не было проблем, ошибок не будет.

### Шаг 6. Сменить пароль

Запусти 1С в режиме **Предприятие**, зайди в *Администрирование* и задай
администратору новый пароль — после сброса он пустой.

## Возможные проблемы

### 1С всё равно просит пароль

Проверь, что обновилась запись в `Params`: платформа ориентируется и на таблицу
`v8users`, и на запись `users.usr`. Если `UPDATE` не затронул ни одной строки —
проверь регистр имени поля (`FileName` в MS SQL, `filename` в PostgreSQL).

### Ошибка синтаксиса в PostgreSQL

Скорее всего, в имени таблицы дефис. Либо используй `v8users_bak`, либо бери имя
в двойные кавычки: `"v8users_tuning-admina"`.

### Таблица v8users_bak осталась в базе

Значит, шаг возврата не выполнился до конца. Проверь, что `DROP TABLE v8users`
прошёл, и переименуй резервную таблицу обратно.

### После сброса не входит ни один пользователь

Восстанови базу из резервной копии и повтори процедуру. Именно поэтому бэкап
обязателен до начала работ.

---

## Рекомендации

- Не работай под общей учётной записью «Администратор» — заведи **именную** учётную запись с административными правами.
- Храни пароли в менеджере паролей, а не в памяти.
- После сброса сразу задай новый пароль: до этого момента база пускает без пароля.
- Резервную копию, снятую перед процедурой, удаляй только после успешной проверки работы базы.
