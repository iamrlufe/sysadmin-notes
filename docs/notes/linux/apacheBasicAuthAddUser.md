# Apache Basic Auth: добавление пользователя

Инструкция подходит для любого сервера с Apache и Basic Auth. В командах замените обозначения на свои значения.

| Обозначение | Что подставить | Пример |
|---|---|---|
| `<сервер>` | Имя или IP сервера | `web01.example.com` |
| `<домен>` | Домен сайта | `example.com` |
| `<пользователь>` | Логин нового пользователя | `ivan` |

Угловые скобки заменяются целиком: `<пользователь>` → `ivan`. Если оставить их, bash примет их за перенаправление.

Подключиться к серверу:

```bash
ssh <ваш-логин>@<сервер>
```

## Где лежит файл паролей

Обычно оба виртуалхоста (HTTP и HTTPS) используют один файл паролей. В примерах ниже это `/var/www/html/.htpasswd`, у вас путь может отличаться. Стандартные конфиги в Debian и Ubuntu:

| Конфиг (sites-enabled) | Порт |
|---|---|
| `000-default.conf` | 80 |
| `000-default-le-ssl.conf` | 443 |

Узнать путь к файлу паролей и конфиги на своём сервере (выводит файл, строку и путь):

```bash
grep -Rni "AuthUserFile" /etc/apache2/sites-enabled/
```

## Добавление пользователя

Пользователь добавляется одной командой `htpasswd` в существующий файл. Флаг `-c` не нужен.

1. Если утилиты нет, установить её:

    ```bash
    sudo apt install apache2-utils
    ```

2. Добавить пользователя. Команда дважды запросит пароль:

    ```bash
    sudo htpasswd /var/www/html/.htpasswd <пользователь>
    ```

3. Проверить, что пользователь появился в файле:

    ```bash
    cut -d: -f1 /var/www/html/.htpasswd
    ```

!!! warning "Флаг -c стирает всех пользователей"
    `-c` пересоздаёт файл. Он нужен только если файла ещё нет. Логин чувствителен к регистру: `Ivan` и `ivan` — разные пользователи.

## Проверка Require и перезагрузка

Нужно ли что-то делать дальше, зависит от строки `Require` в конфигах сайта.

```bash
grep -n "Require" /etc/apache2/sites-enabled/000-default.conf /etc/apache2/sites-enabled/000-default-le-ssl.conf
```

| Что в конфиге | Что делать |
|---|---|
| `Require valid-user` | Ничего. Пускает любого пользователя из файла, доступ работает сразу. |
| `Require user admin ...` | Дописать `<пользователь>` в строку в **обоих** конфигах, затем перезагрузить Apache. |

Перезагрузка нужна только после правки конфигов. Файл `.htpasswd` Apache перечитывает на каждый запрос.

```bash
sudo apache2ctl configtest && sudo systemctl reload apache2
```

## Проверка доступа

Доступ проверяется с сервера или любой машины через curl. Ответ `200` означает, что вход работает, `401` — что логин или пароль не приняты.

```bash
curl -I -u <пользователь> https://<домен>/
```

## Шпаргалка

| Задача | Команда |
|---|---|
| Добавить пользователя или сменить пароль | `sudo htpasswd /var/www/html/.htpasswd <пользователь>` |
| Удалить пользователя | `sudo htpasswd -D /var/www/html/.htpasswd <пользователь>` |
| Список пользователей | `cut -d: -f1 /var/www/html/.htpasswd` |
| Проверить пароль | `htpasswd -v /var/www/html/.htpasswd <пользователь>` |
| Проверить конфиг и перечитать | `sudo apache2ctl configtest && sudo systemctl reload apache2` |

## Безопасность и замечания

- Файл `.htpasswd` часто лежит в корне сайта. Штатно Apache отдаёт 403 на `.ht*` (правило `<FilesMatch "^\.ht">` в `apache2.conf`). Проверить: `curl -I https://<домен>/.htpasswd` должен вернуть `403`. Надёжнее перенести файл за пределы `/var/www`, например в `/etc/apache2/.htpasswd`, и поправить `AuthUserFile` в обоих конфигах.
- Basic Auth передаёт пароль в base64, без шифрования. Входить только по HTTPS.
- Резервные копии вроде `000-default-le-ssl.conf.bak` в `sites-enabled` Apache не подключает: он читает только `*.conf`. Их лучше убрать, чтобы не путаться.
